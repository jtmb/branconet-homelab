# Bounded native metadata listing optimization

Implementation base: integration owner `6651685bf17ae1cf1b98e3a51cc75d81dfba30e3`. This change owns only `src/lib/cluster-secrets.ts`, `src/lib/secret-client.ts`, exclusive concurrency regressions and native scheduling documentation. UI, auth, cluster-cache/HTTP serialization, readiness behavior, deployment manifests, Dockerfiles and the frozen benchmark workload remain outside this task.

Native production flat metadata lists now opt into four namespace workers. Every worker shares one 15-second deadline, 10,000-item/32-MiB received-body budget and the existing global four-request/64-queued native transport pool. Complete projected metadata is returned in configured namespace order only after every worker succeeds. Compatibility `SecretStore` callers retain serial scheduling unless explicitly opting into one to four workers. Invalid worker settings and namespaces fail before native requests.

Production flat metadata lists start at 200 objects per namespace. The optional transport setting is restricted to 20 or 200; compatibility `createSecretTransport()` callers keep 20. A locally oversized full-list GET reduces directly from 200 (or 20) to 10, then 5/2/1, retaining its cursor and smaller limit for that namespace. This preserves the maximum four reductions and skips a second over-cap 20-object attempt: an extra charged four-MiB prefix could otherwise reject the previously operable 80-by-256-KiB inventory near the shared 32-MiB ceiling. A 25-by-256-KiB inventory succeeds at limit10; three one-MiB objects succeed at limit2, with the same successful page counts and reductions as the prior transport. Four-MiB response, 900-KiB write, eight-second request/authentication and all TLS/scope checks remain unchanged. There is no native retry on error/mutation, value cache, DB fallback or stale native response. Exact objects/key spellings, binary/empty data and empty objects remain native-authoritative. Full bodies are projected page by page to metadata; parallel work can increase simultaneous transient buffers and is not a process-RSS ceiling.

The larger initial window trades fewer requests for more API-producer work on oversized pages. The client stops before buffering a chunk that crosses the existing ceiling, but the API may already have serialized a larger body. Producer attempted-body bytes differ from client-delivered bytes and do not prove actual wire transfer. A namespace mixing small records and large records can also need an extra accepted page after the direct fallback. The reduced size is local to that namespace and operation; there is no learned global or native-value cache. Metadata-only readiness/history requests and native mutations retain their original behavior.

The shared budget records delivered chunks synchronously across workers, including rejected prefixes and late chunks after cancellation. Any failed scope, item/byte ceiling or deadline fails the whole list and aborts only that operation's authentication wait, active requests and queued entries. Workers settle before returning the fixed error; partial summaries are not returned. Other operations keep their own budgets and request slots. An already received final chunk can put the diagnostic counter above the ceiling; it is charged and rejected before buffering rather than silently discarded from accounting.
