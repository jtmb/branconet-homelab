Trigger/description: “Use when testing a managed container locally with Kubernetes-backed settings, or adding a BORTUS secret-run profile.” Purpose: build locally without requesting plaintext, distinguish fixture and credential-backed evidence, and leave no running test resources. Inputs: intended image/service, authorized profile ID (from operator or project docs, not guessed), objective, and whether testing changed code or an approved digest.

Workflow: (1) Read repo rules and its working state; use `scope-and-continuity` if uncertain. (2) Reuse existing local build/test scripts; validate changed code with synthetic fixtures and apply `meaningful-testing`. (3) For an approved live-compatible image call `bortus.secrets_run` with only its profile; do not run a fallback Secret read or infer missing grants from manifests. (4) Report run ID, fixed outcome, tested artifact and whether it was fixture, dev-backed or explicitly live. For denied/unavailable request one named approval or direct operator action; for busy do not loop; for uncertain cleanup contact the operator with the run ID. (5) Update relevant docs when profile requirements change; hand off evidence, never secret material. Authoritative references: C-1–C-3, repository rules and the operator’s installed profile policy.
